# 外出申請

Edge 95 / IE11 を対象にした外出申請アプリです。自宅ではCSV、本番では庁内SharePoint Serverの３リストを使用します。画面タイトルは「外出申請」のみです。

## 自宅で起動

1. Node.js 18以上とVS Codeを用意します（追加のnpmパッケージは不要）。
2. このリポジトリを取得し、**gsフォルダーそのもの**をVS Codeで開きます。
3. **F5 → 外出申請（CSVテスト）**を実行します。
4. 既定ブラウザで `http://localhost:8787` が開きます。

F5でブラウザが開かない場合は上記URLを手動で開いてください。ターミナルからは `npm start` でも起動できます。別のPCには公開せず、127.0.0.1だけで待ち受けます。F5停止後に起動し直してもデータは保持します。

### テスト用ログイン

**全員の初期パスワード：`test1234`**（架空の自宅用データのみ）。

| 利用者ID | 名前 | 区分 | 外出証番号 |
|---|---|---|---|
| admin | 管理者（テスト） | 全区分＋管理権限 | ― |
| a001 | 申請 太郎 | 申請者 | 010 |
| a002 | 申請 次郎 | 申請者 | 011 |
| b001 | 承認 一郎 | 承認者 | ― |
| b002 | 承認 二郎 | 承認者 | ― |
| d001 | 当直 三郎 | 当直 | ― |

- a001の承認順序：b001 → b002。a002：b002の１人だけ。
- 初回起動で翌日17:00～24:00のサンプル申請を１件作成します。
- 管理者で「利用者設定」を開き、部隊・階級・氏名・外出証番号・メール・区分・承認順序・パスワードを編集できます。
- 管理者は追加の管理権限です。ログインの業務区分は申請者／承認者／当直の３種類です。
- 外出証番号は有効な利用者間で重複不可、先頭の0も保持します。

### 動作確認の順序

1. a001で申請入力。外出先は20文字以内、行動予定は複数行・任意です。過去履歴ボタンで同じ申請者の内容を再利用できます。
2. b001で承認。b002はこの承認が終わるまで承認できません。
3. b002で承認。本人宛の承認完了通知を記録します。
4. d001で「当直」→外出証番号010を検索。飲酒・車両運転の確認チェックを付けて交付します。
5. 同じ番号で検索し、同様の確認後に返納します。時刻と操作者は自動記録です。
6. 「日別・期間別出力」で日付と部隊を指定して印刷します。前日から続く外出も対象です。
7. 全員が交付前の申請を編集できます。変更すると承認を最初からやり直し、元の承認履歴は保持します。

申請者・承認者・当直を切り替えるときはログアウトしてください。同一ブラウザの複数タブはCSV版ではログインCookieを共有します。別人で同時確認する際は別ブラウザ／別プロフィールを使用してください。

## CSV

初回起動時に生成します。

| ファイル | 内容 |
|---|---|
| data/users.csv | 利用者、個人別パスワード、承認経路 |
| data/requests.csv | 申請、承認、交付・返納、通知記録 |
| data/audit.csv | 操作者、日時、操作、変更前後 |

列は `id,payload` の２列、UTF-8 BOM付き、payloadはJSONです。日本語、改行、カンマ、引用符を保持します。保存は一時ファイルからの置換を使い、３ファイルの更新途中で終了した場合はtransaction.jsonから次回起動時に復元します。

サーバー停止中に３CSVをセットでコピーしてバックアップしてください。初期化したい場合はdataフォルダーを別名で退避してから再起動します。利用中CSVはGit管理しません。`GS_DATA_DIR` 環境変数で保存先を変更できます。ポートは `PORT`（既定8787）。複数のサーバーで同じデータフォルダーを同時使用しないでください。

## 簡易暗号化と識別

- パスワード・外出先・行動予定は、固定キーXOR＋16進表記の**簡易難読化**です。強固な暗号や秘密保管機能ではありません。ソースを読める人は復号できます。ご指定の「リスト上でそのまま読めない程度」に合わせています。
- 外出先・行動予定の変更履歴も暗号化状態で保存します。パスワードは履歴・一般のCSV API応答に含めません。
- 個人IDと個人別パスワードでログインし、申請の「次の承認者ID」と照合します。
- CSV版は操作アカウントを「テスト：氏名」と記録します。
- SharePoint版は `/_api/web/currentuser` の表示名とLoginNameを取得します。ブラウザのプロフィール名ではありません。
- SharePointログイン名を利用者情報に登録すると、アプリのIDとの一致も検査します。
- 緊急連絡先はありません。

## SharePoint Serverへ切り替える

1. サイトのリスト作成権限を持つ管理者が、Windows PowerShellで次を実行します。UsersCsvには、テスト用データを整理し本番の利用者・パスワードに変更したCSVを指定してください。公開リポジトリに本番CSVを置かないでください。

   ```powershell
   .\tools\setup-sharepoint.ps1 -SiteUrl 'https://庁内サイト/sites/outing' -UsersCsv 'C:\作業\users.csv'
   ```

   既存の利用者が１件でもあればインポートをスキップします。既存データは削除しません。途中までインポートされた場合もスキップするので、件数を確認し、不足分を管理者画面で登録してください。

2. 作成するリストは次の３つです。

   | 名前 | 列 |
   |---|---|
   | GS_Users | Title：利用者ID（重複不可）、Payload：複数行プレーンテキスト |
   | GS_Requests | Title：申請ID（重複不可）、Payload：複数行プレーンテキスト |
   | GS_Audit | Title：履歴ID（重複不可）、Payload：複数行プレーンテキスト |

3. `public/config.js` のmodeを `sharepoint`、siteUrlを実際のサイトURLに変更します。
4. `public` 内の全ファイルを同じフォルダーに配置し、SharePointと同じオリジンでindex.htmlを配信します。HTMLのブラウザ表示を許可するサイト設定が必要です。Nodeサーバーは本番では使用しません。
5. 実際のSharePoint Serverで、ログイン名取得・読み書き・同時更新エラー・日本語表示を確認してください。

ETag / IF-MATCHを使用して同じ項目の競合更新を検出します。大人数・長期運用の性能、リストしきい値、組織の権限設定は本番環境で確認が必要です。

**SharePoint版の制約：** パスワード・役割の照合はブラウザ側です。SharePointリスト自体への編集権限がある人が直接RESTやリストを操作することまで防ぐものではなく、改ざん防止の監査ログを保証しません。ログイン前からデータアクセスを厳密に制限するにはSharePoint側の権限／サーバー側処理が必要です。

## メール通知

- 申請完了 → 最初の承認者
- 各承認完了 → 次の承認者
- 最終承認完了 → 申請者
- 本文：申請者、外出期間、区分、画面リンク。外出先・行動予定は載せません。
- 自宅CSV版は**模擬送信のみ**。外部にメールを送りません。詳細画面・操作履歴で結果を確認できます。
- SharePoint版も初期値は `mailMode: 'simulate'` です。
- 庁内SharePoint Serverの送信設定とAPI可用性を確認後、`mailMode: 'sharepoint'` にすると `/_api/SP.Utilities.Utility.SendEmail` を呼びます。宛先の登録状態・許可範囲・SMTP設定に依存します。
- 送信受付は受信完了の保証ではありません。失敗は申請詳細に表示・記録します。タイムアウト時の二重送信を避けるため自動再送はしません。失敗・未処理は管理者が到達状況を確認し、必要に応じて別途連絡してください。
- SharePointの本体保存・操作履歴・メール送信は一括トランザクションではありません。途中失敗時は保存済みの範囲をエラーに表示します。画面を再読み込みし履歴を確認してください。
- 本番メール送信は未検証です。SharePoint Online向けの送信方式ではありません。

## 印刷

A4横を初期設定とし、日別・期間別・部隊・状態・外出区分で抽出します。行動予定は「行動予定も印刷」で含められます。ブラウザの印刷設定でヘッダー／フッターをオフにするとURL・ページタイトルを除けます。承認者数は固定せず全員表示します。

## 検証

`npm test`：業務ルール、暗号化・CSV往復、永続化、競合、ログイン・ログアウト、API処理を検証します。

`tests/browser_test.py`：Playwrightで画面操作を確認するテスト。**使い捨てデータフォルダーでサーバーを起動してから**実行してください。既定ブラウザが未インストールなら `GS_CHROMIUM` にChromiumの実行ファイルを指定できます。テストはサンプル利用者a002のパスワードを変更します。

作成環境ではブラウザ起動がOSのソケット制限で失敗し、共有ブラウザもローカルサーバーへ接続できなかったため、画面テストは未完了です。Edge 95・IE11・SharePoint Serverの実機検証も未実施です。フロントエンド全JSはES5構文検査済み。IE11でも日付を選べる独自カレンダーを使用し、外部CDN依存はありません。
